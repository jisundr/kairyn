# Learnings

Stages append here.

- 2026-11-22 [requirements] This repo installs its own plugin, so its dev harness and the consumer harness share `CLAUDE.md`, `.harness/README.md` and `budgets.yml`. Only one `harness-docs` marker pair may exist in a file (`harness_docs.py` updates the first). Keep kairyn's own `CLAUDE.md` text under budget so the plugin block fits.
- 2026-11-22 [build] This repo's `.harness/README.md`, `budgets.yml` and `task-lifecycle.md` are dev docs at consumer paths. Upgrade reports them as conflicts once; delete each `.kairyn-new` to keep ours.
- 2026-11-22 [build] `/kairyn:check write` rewrites the doc index in the CLAUDE.md block, so the block's hash leaves the index out. Otherwise every check would make upgrade see an edit.
- 2026-11-22 [build] Headless `claude -p --permission-mode acceptEdits` refuses Bash beyond simple read-only commands: a globbed `grep` "requires approval". Stage steps that must work in evals use Read and Glob, not shell pipelines.
- 2026-11-22 [build] On macOS the filesystem ignores case: `GRILL.md` and `grill.md` in one folder are the same file. Draft stage and command files in separate folders.
- 2026-11-22 [build] A template that lists every section makes the model fill every section. Asking for all four non-functional needs made it invent them (judge no_invention 3.7); "state only what a source states, else not applicable" brought it to 4.1.
- 2026-11-22 [requirements] The MODEL-ROUTING stage targets apps that call an LLM API. kairyn has none, so "model routing" here means the `model:` of a stage subagent. Claude Code loads agents at session start, so agents generated by a SessionStart hook can lag one session.
- 2026-11-23 [exit] A skill's `model:` applies to its own turn only. Later turns in the same task, such as grill answers and the approval reply, run on the session model.
- 2026-11-23 [exit] A 2-run smoke does not vouch for a model choice. `requirements` passed on Sonnet at 2 runs and failed the 10-run gate (guessed timestamps, plain language).
- 2026-11-23 [grill] `evals/checks.py` `structural_problems` expects requirements to hand the task to `design` after approval. A new stage after design must change `design_run_problems` and the design eval the same way.
- 2026-11-23 [requirements] To lint a stage output by hand, import `evals/checks.py` with both `evals` and `tests` on `sys.path`: it imports `split_front_matter` from `tests/helpers.py`.
- 2026-11-23 [build] An LLM judge must see every file the stage could read. The design judge got only `report.py` and scored true README facts as invented (no_invention 2.3).
- 2026-11-23 [exit] pytest collects any imported function whose name starts with `test_`. Name check functions in `evals/checks.py` without that prefix (`design_test_plan_problems`).
- 2026-11-23 [exit] A path check must accept a later mention of a file marked `(new)` once. Designs name a created file again in the test plan without the mark.
- 2026-11-23 [requirements] To name a hedge word in a stage output, put it in backticks. `checks.ste_problems` skips inline code but counts a quoted "word".
- 2026-11-23 [exit] The writing rule aims at ASD-STE100 about 80% of the way. A hedge that only quotes the eval request does not block a task when `plain_language` passes its gate.
- 2026-11-23 [exit] A line in `_template.md` Writing changes every stage. Run all five dependent evals at 10 runs, not only the eval of the stage you meant to fix.
- 2026-11-23 [exit] `/run-evals` with no arguments runs every eval whose dependencies changed, at 10 runs. `--all-evals` with names runs only those names. For a cheap check, name the eval and add `--runs 2`.
- 2026-11-23 [exit] Give every stage output a template. Without one, grill on Sonnet wrote `# Concept` for `## Concept` in 2 of 10 runs. Read the failure reasons before you blame the model.
