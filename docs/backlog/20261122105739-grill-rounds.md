# Grill asks one question per message, not rounds

**Raw request:** "What id you recommend baed on matth skill?" … "Yes. I agree" (Jayson, 2026-11-22, Claude Code session) Source: Matt Pocock's `grilling` skill, `mattpocock/skills`, `skills/productivity/grilling/SKILL.md`.

**Problem (confirmed by Jayson De los Reyes, 2026-11-25):** `plugin/stages/GRILL.md` asks one question per message, so a long design takes many turns. We would know it improved when an eval shows each grill message asks the whole frontier, numbered, each with a recommended answer that "yes" accepts.

**Evidence:**
- `grilling` asks every question whose prerequisites are settled in one round, then recomputes the frontier.
- Its docs: questions arrive in a few rounds; one at a time is an opt-in line in `CLAUDE.md`.
- It sends a subagent for repo facts and asks the other questions meanwhile.
- It stops on questions talk cannot answer and prototypes instead.
- `GRILL.md` is at 448/500 tokens, but rounds rewrite step 4, its `purpose` line, the `one_question` metric and the 4-turn scenario of `evals/promptfoo/grill.yaml`.

**Notes:** Keep `CONCEPT.md`: kairyn stages pass results through files, like `grill-with-docs`. Rewrite the grill eval first (evals before instructions). Split from grill-requirements (closed at exit, in git history).

**Decided (2026-11-25):** Rounds by default, at most 3 questions per message: a "yes" to a full frontier hides decisions. No-gos: a subagent for repo facts (step 2 reads the repo; a subagent costs each turn) and prototypes instead of questions. No small slice: any change to the question contract re-runs the multi-turn grill eval.
