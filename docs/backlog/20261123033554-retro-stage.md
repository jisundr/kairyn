# Learnings pile up and are never turned into rules

**Raw request:** "let's add to backlog adding retro to convert learnings into something" (Jayson, 2026-11-23, Claude Code session)

**Problem (AI draft, needs a human to confirm):** Every stage appends to `.kairyn/learnings.md`, and nothing ever removes an entry. A learning only helps when an agent reads it at the right time. A durable rule belongs in a stage file, a harness doc, a test or a script. We would know it improved when a retro run moves each learning to its home or drops it, and `learnings.md` stays well under budget.

**Evidence:**
- `.kairyn/learnings.md` is at 969/1000 tokens with 19 entries after two days. The next few entries push it over budget.
- Some entries are already rules elsewhere. Example: the clock rule is also in `_template.md` and `task-lifecycle.md`.
- One entry went stale and was fixed by hand at exit (the `structural_problems` handoff).
- No playbook in `knowledge-base/03 Playbooks/` covers a retro yet.

**Notes:** Candidate homes: a stage step, a `.harness` doc, a test or check, a script. Principle 1: a learning that must always hold becomes a script or a test, not an instruction. Maybe an optional stage like exit, run after a few tasks. Learnings move or go; they are never only rewritten.

**Recheck (knowledge-base `be5dbfa`):** Two playbooks now hold a retro step: `Agents/06 Using Bots` step 10 (each mistake gets a new check or a memory entry) and `SDLC/07` step 10 (feed gaps back to the stage that should have caught them). Both prefer a deterministic check over a memory entry.
